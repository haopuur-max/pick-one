# PICK ONE

**不给你推荐列表，只给一个答案。**

一个购物决策工具。你把纠结的 2–4 件商品丢进去，它告诉你选哪一个、你为此放弃了什么，以及——当它判断不出来的时候——诚实地说选不出来。

🔗 **[打开体验 →](https://haopuur-max.github.io/pick-one/)**

---

## 为什么做这个

买东西之前搜一圈，得到的永远是"十款值得买的 XX 推荐"。看完之后要选的东西从 3 个变成 10 个。

信息不是不够，是太多了。缺的不是选项，是**收敛**。

所以这个产品的第一条设计原则是：**不输出列表。**

## 它怎么工作

七步流程：

1. **说出纠结** —— 用自然语言，不填表单
2. **确认理解** —— 把你的话拆成"场景 / 在意 / 不能接受"，你可以改
3. **挑出冲突** —— 找到互相拉扯的那一对（比如"展开是大屏"↔"合起来要轻薄"）
4. **问一句关键问题** —— 只问能定音的那一个，不做连环问卷
5. **给出答案** —— 一个，带理由
6. **说清代价** —— 你放弃了什么，明写出来
7. **可以反驳** —— 不同意就说，它重新算

## 五个设计决策（以及被否掉的做法）

| 决定 | 否掉的做法 | 为什么否 |
|---|---|---|
| 只给一个答案 | 前三名 + 匹配度百分比 | 92% 和 89% 的差别是编的，用户会当真 |
| 只暴露一组冲突 | 六维雷达图 | 六条边同时张着等于没有重点 |
| 只问一个问题 | 固定五题问卷 | 多数情况前两题就能定音，剩下的只是消耗耐心 |
| 六个通用维度 | 每品类一套专属维度 | 更准，但每加一个品类就要重写引擎 |
| 判不出来就承认 | 总是输出最高分的那个 | 被抓到一次硬凑，之前所有对的结论一起失效 |

## 技术

单文件 HTML，无构建、无依赖、离线可跑。

- 判断引擎是真的：六因素加权 + 冲突检测 + 缺省兜底，不是预设脚本
- AI 只负责措辞，不负责判断。输入侧脱敏，输出侧有一道闸门拦截内部字段泄漏
- 商品图取不到时退回纯排版，不留白框
- 移动端适配、键盘可达
